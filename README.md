# RMS — Restaurant Management System

Веб-система управления рестораном с модулем **поддержки принятия решений**:
она не только принимает заказы, но и сама подсказывает владельцу,
что рекламировать, где поднять цену, какое комбо предложить и когда усилить смену.

**Стек:** Go + Gin · PostgreSQL (pgx) · JWT + bcrypt · HTML/CSS/JavaScript (fetch, SVG-графики без библиотек)

## Запуск

```bash
# 1. Миграция (себестоимость, проверки статусов и ролей, индексы)
psql "postgres://postgres:postgres@localhost:5432/restaurant_management" \
     -f backend/database/migrations/001_analytics.sql

# 2. Демо-данные: меню, сотрудники, 250 клиентов, ~15 000 заказов за 180 дней
cd backend && go run ./cmd/seed          # повторно с очисткой: go run ./cmd/seed -reset

# 3. Сервер (API + фронтенд) → http://localhost:8080
go run ./cmd/server
```

Демо-сотрудники (пароль `password123`): `waiter@rms.kz`, `cook@rms.kz`, `owner@rms.kz`.

## Роли

| Роль | Что может |
|---|---|
| customer | меню, корзина, заказ, история, отмена заказа до подтверждения |
| waiter | очередь заказов: принять, отменить, выдать гостю |
| cook | очередь заказов: начать готовить, отметить готовность |
| admin | всё: блюда, категории, заказы, аналитика |
| owner | дашборд и аналитика |

Жизненный цикл заказа проверяется на сервере (`handlers/orders.go`):

```
pending → confirmed → preparing → ready → completed
   └────→ cancelled
```

| GET | `/api/categories`, `/api/dishes`, `/api/dishes/:id` | все |

| POST | `/api/orders/:id/cancel` | владелец заказа |

## Модуль аналитики и поддержки решений

Все расчёты — в `backend/handlers/analytics.go`: агрегаты считает PostgreSQL,
правила классификации и рекомендаций написаны на Go.

| Анализ | Метод | Какое решение даёт |
|---|---|---|
| KPI | выручка, заказы, средний чек, валовая прибыль vs прошлый период | общая динамика |
| Инженерия меню | матрица Kasavana & Smith: популярность (порог 70% от 1/N) × маржа с порции (порог — средняя) → ⭐ звёзды, 🐴 лошадки, ❓ загадки, 🐶 собаки | что рекламировать, где поднять цену, что убрать |
| Анализ корзин | ассоциативные правила: support, confidence, lift | комбо-наборы, «с этим берут» на странице блюда |
| Нагрузка | средние заказы по дню недели × часу | график смен персонала |
| Рекомендации | правила поверх всех анализов | список конкретных действий для владельца |

### Проверка на заложенных закономерностях

Генератор (`backend/cmd/seed`) специально закладывает в данные закономерности,
а аналитика должна найти их сама, не зная о них:

| Заложено | Найдено системой |
|---|---|
| к бургеру берут фри в 65% случаев | confidence «Чизбургер → Картофель фри» ≈ 67% |
| к суши берут Мохито в 30% | «Филадельфия → Мохито» ≈ 34% |
| пики в обед и вечер, выходные ×1,4–1,55 | тепловая карта: Сб/Вс 13:00 и 19:00 |
| «Дракон» — дорогой и маржинальный, но редкий | класс ❓ «загадка» → рекомендация «прорекламировать» |
| «Чизбургер» — ходовой, но с низкой маржой | класс 🐴 «лошадка» → «поднять цену на ~10%» |
